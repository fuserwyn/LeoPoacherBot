# Задача трекера #53

Задача #53.

Для админов нужно сделать возможность при составлении задачи выбирать возможность проставлять чекбокс нужен ли аппрув других участников перед выставлением задачи 

Если он проставлен, то другим админам приходит уведомление, где они аппрувят задачу, если собрано два аппрува задача едет на доску в статус выполняется, давай еще добавим колонку на доску аппрув между ожидается и выполняется 


Если админ в уведомлении ставить не аппрув, то он может либо изменить описание чтоб его проставить, либо отмерить вовсе с и без комментариями

Если это автор задачи не хочет он может не проставлять этот чек бокс, по умолчанию он не проставлен

## выполнение

Сделано аппрув-флоу для задач трекера (#53).

**База и модель**
- Поля `needs_approval` и `approvals` (JSON-массив id админов) в `pack_tracker_tasks`
- Миграция через `EnsureTrackerSchema`

**Бэкенд**
- Колонка `approve` между «Ожидает» и «В работе»
- При создании с чекбоксом задача попадает в «Аппрув», другим админам уходит Telegram-уведомление
- Кнопки: «Аппрув» / «Не аппрув» → изменить описание, отменить с комментарием или без
- После 2 аппрувов задача переходит в «В работе» и запускается агент
- Автор не может аппрувить свою задачу; ручной перенос в работу без аппрувов заблокирован
- API-операция `approve` для мини-аппа

**Фронтенд**
- Чекбокс «Нужен аппрув других админов» (по умолчанию выключен)
- Колонка «Аппрув» на доске
- Бейдж с счётчиком аппрувов на карточках

Локальный коммит не создан: в окружении не настроен git user (по правилам git config не трогал). Изменения в рабочей директории готовы к пушу трекером.
