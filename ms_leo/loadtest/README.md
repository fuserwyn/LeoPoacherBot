# 24h load test: 5000 users

This folder contains a realistic load profile for `ms_leo` miniapp API:
- 5000 synthetic users
- 24-hour activity profile (night low, evening peak)
- mixed behavior: feed reads, group chat messages, Leo DM, `#training_done`, profile reads

## 1) Prerequisites

- `k6` installed
- reachable API URL
- bot token for valid Telegram Mini App `init_data` generation

## 2) Run 24h scenario

```bash
cd ms_leo
BASE_URL="https://your-service.up.railway.app" \
BOT_TOKEN="<telegram-bot-token>" \
MONETIZED_CHAT_ID="-1001234567890" \
USERS_TOTAL=5000 \
RATE_PER_SEC=5 \
PRE_ALLOCATED_VUS=600 \
MAX_VUS=5000 \
k6 run loadtest/k6-24h-5000-users.js
```

## Autostart after rollout (GitHub Actions)

Added workflow: `.github/workflows/railway-smoke-loadtest.yml`.

It runs automatically on push to `main` (and manually via `workflow_dispatch`), waits 2 minutes for rollout, then starts the 15-minute smoke scenario against Railway.

Set these GitHub repository secrets:
- `RAILWAY_MS_LEO_URL` (example: `https://msleo-xxx.up.railway.app`)
- `TELEGRAM_BOT_TOKEN`
- `MONETIZED_CHAT_ID` (example: `-1001234567890`)

If you do not want auto-run on every push, remove `push` trigger and keep only `workflow_dispatch`.

### Main env vars

- `BASE_URL` - target API origin
- `BOT_TOKEN` - required, used to generate valid signed `init_data`
- `MONETIZED_CHAT_ID` - optional; if set, load users are pinned to this pack chat context
- `USERS_TOTAL` - size of synthetic population (default `5000`)
- `TEST_DURATION` - scenario duration (default `24h`, for smoke use `10m`/`15m`)
- `RATE_PER_SEC` - global iteration arrival rate (default `5`)
- `PRE_ALLOCATED_VUS`, `MAX_VUS` - k6 capacity settings

## 3) Outputs

After run you get:
- `loadtest-summary.json` (auto generated by k6 `handleSummary`)
- stdout with latency/error stats from thresholds

## 4) Railway CPU/RAM and cost

1. Open Railway metrics for the service and extract average CPU + RAM over the same 24h window.
2. Run the estimator:

```bash
python3 loadtest/railway_cost_estimate.py \
  --avg-cpu 0.90 \
  --avg-ram-gb 1.40 \
  --hours 24 \
  --cpu-price 0.000463 \
  --ram-price 0.000231
```

Use your actual Railway pricing values for precise estimates.

## 5) Recommended rollout

Before full 24h:
1. Smoke: `USERS_TOTAL=200`, `RATE_PER_SEC=1`, duration 10-15 min (edit scenario duration in script).
2. Baseline: 1000 users, 1-2 hours.
3. Full: 5000 users, 24 hours.

This sequence reduces the risk of burning budget on misconfiguration.
